# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

EasyWrite: an AI copilot for writing Chinese government/enterprise technical bid documents (技术标书). FastAPI backend + Vue 3 SPA. Code comments, docstrings, UI strings, and docs are in Chinese — keep new ones in Chinese to match. `README.md` (usage, API table), `walkthrough.md` (design rationale), and `implementation_plan.md` (v0.2.0 refactor log) are the reference docs.

## Commands

```bash
# Backend (run from backend/ — .env is resolved relative to CWD; data paths are absolute)
pip install -r backend/requirements.txt
cd backend && python -m uvicorn app.main:app --port 8790 --reload   # UI at /, API docs at /docs

# Frontend
cd frontend && npm install
npm run dev     # :5173, proxies /api -> 127.0.0.1:8790 (backend must be running)
npm run build   # outputs to backend/app/static/ (committed; FastAPI serves it in production)
npm test        # Vitest + @vue/test-utils + jsdom; specs in src/**/__tests__/*.test.js

# Tests (run from repo root; conftest inserts backend/ into sys.path)
python -m pytest tests/ -q
python -m pytest tests/test_api.py::test_full_lifecycle -v

# Lint (repo root; config in ruff.toml; pip install -r backend/requirements-dev.txt)
python -m ruff check .
```

ruff runs E/F/W/B (E501, E741, B905 ignored; FastAPI `Body()`/`File()` defaults whitelisted); keep it clean. No formatter is configured. After changing `frontend/src`, run `npm run build` so the committed `backend/app/static/` bundle stays in sync. On this machine `pip` on PATH belongs to a different Python than `python` — use `python -m pip`.

`tests/conftest.py` sets `DATA_DIR`/`DB_PATH`/other path env vars to a temp dir and blanks `LLM_API_KEY`/`EMBEDDING_API_KEY` *before* importing the app, so tests never touch `backend/data/` and always run in offline/mock mode, asserting deterministic rule-based fallbacks. Settings, the DB engine and the JSON-backed managers resolve paths at import time — any new runtime path must derive from `settings` so this isolation keeps working (`tests/test_runtime_isolation.py` checks it).

Real public tenders (ccgp.gov.cn, Chongqing template) live in `downloads/ccgp_2026-10-06/` (git-ignored, not in the repo). `tests/test_tender_parsing.py` runs against them when present (each package's rubric must total 100) and skips otherwise; synthetic docx fixtures with merged cells cover the same logic unconditionally. Validate parser/extractor changes against these files, not only the synthetic ones. `downloads/ccgp_2026-10-06/pdf/` holds the same five tenders exported to PDF by Word (`NN_bookmarks.pdf` with heading bookmarks, `NN_plain.pdf` without; regenerate via Word COM `ExportAsFixedFormat` if missing); `tests/test_pdf_parsing.py` checks their rubrics total 100 and that bookmark headings match the docx. `downloads/ccgp_2026-10-06/0N_*.pdf` are five *different* real tenders published as PDF by central/other-province agencies (WPS- or Aspose-generated: running chapter headers, 3-line headers, white paragraph shading, per-page line spacing, broken WPS bookmarks, "A包" packages, "评审因素" header spanning two columns, points written inside factor names); `tests/test_pdf_layout_variants.py` checks each package totals 100, the package labels, heading mode and purchaser. When changing the PDF parser or scoring extractor, run both real-file sets.

Don't put CJK characters in `strftime()` format strings — it raises `UnicodeEncodeError` on Windows; build Chinese date strings with f-strings.

## Architecture

### Backend layout (`backend/app/`)
- `main.py` — mounts 11 routers from `api/` under `/api/v1`, serves `static/` SPA with a history-mode fallback (`/{full_path}` returns `index.html` for `text/html` requests).
- `api/` — thin routers per domain; business logic lives in `services/`.
- `core/` — module-level singletons imported everywhere: `llm_client`, `embedding_client`, `ai_settings_manager`, `task_manager`, `settings`. `core/request_context.py` holds the `current_project_id` contextvar, set by `ProjectContextMiddleware` in `main.py` from `/api/v1/project/{id}/…` URLs (pure ASGI, so SSE streams inherit it); it propagates into sync endpoints, background tasks and LLM usage rows.
- `db/` — SQLModel + SQLite (WAL) at `backend/data/easywrite.db`. `init_db()` runs at import of `db/database.py`. Tables: `projects`, `kb_documents`, `kb_chunks` (embeddings as float32 BLOB + `embedding_version` fingerprint), `kb_items`, `tasks` (background task records), `llm_calls` (per-request LLM usage). Nested structures (outline tree, facts, deviation matrix, tender analysis, tender section tree `tender_structure_json`) are JSON text columns, always loaded/saved whole. `section_versions` holds section history. `create_all` never alters existing tables, so `_add_missing_columns()` in `db/database.py` runs `ALTER TABLE … ADD COLUMN` for new model fields on startup — new columns need a default.
- `services/project_store.py` — the only path to project persistence; converts `ProjectModel` rows ↔ Pydantic `Project` (in `models/schemas.py`). Writes go through `project_store.update(project_id, mutate)`, which re-reads the latest row under a process-wide lock and saves whatever `mutate(project)` changed. Never `get()` → slow work (LLM call, streaming, background task) → `save()` a stale snapshot — that overwrites concurrent edits (e.g. editor autosave during a stream). Do LLM work outside `mutate`; raising `HTTPException` inside it rolls back. `find_node()` locates outline nodes; `ProjectNotFound` maps to 404 in `main.py`.
- Some state is JSON files, not SQLite: `data/ai_settings.json`, `data/templates.json`, `data/enterprise_assets.json` (`ai_settings.json` holds API keys in plaintext and is git-ignored, created on first save; the other two are git-tracked seed data).

### LLM configuration and "honest mode" signalling
All LLM calls go through `core/llm_client.py` (OpenAI-compatible; sync + async clients). Config comes from `ai_settings_manager` (UI-editable, hot-reloaded via `llm_client.reload_config()`), falling back to env vars in `core/config.py`. Embeddings are configured separately (`embedding_client`) and are optional. Provider presets (`PROVIDER_PRESETS` in `ai_settings_manager.py`, `EMBEDDING_PRESETS` in `embedding_client.py`) list only models that are currently sold, checked against each vendor's model list / deprecation notices on `PRESETS_REVIEWED`; `RETIRED_MODELS` maps retired IDs to replacements — presets must never contain them (test-enforced), `fetch_online_models` filters them out of live `/models` lists (`curate_online_models`, recommended first), and Settings offers a one-click replace when the saved model is retired. When updating presets, verify IDs online and bump `PRESETS_REVIEWED`.

Every real model request (chat, stream, embedding, connection test — including escalation retries, rate-limit retries and failures) writes one `llm_calls` row via `core/llm_usage.py` (`record()` / `StreamMeter`): latency, first-token time for streams, provider-reported `usage` (left NULL when absent — never estimated), status `ok/truncated/empty/error/aborted`, project (from the contextvar) and `purpose`. Pass `purpose="…"` on every `chat_completion*` call (labels mirrored in `frontend/src/utils/llmUsage.js`). Streams send `stream_options.include_usage`; if the provider rejects it, the client retries without and stops sending it until `reload_config()`. Mock fallbacks write nothing. `GET /ai/usage?days=&project_id=` aggregates (Settings → 模型调用记录); rows older than 180 days are pruned at startup.

Core rule across the codebase: **never fabricate data when the LLM is unavailable**.
- `chat_completion*` falls back to `_mock_bid_generation` and sets mode `"mock"`; `llm_client.get_mode()` must be propagated in API responses as `mode` so the frontend shows the offline banner.
- `chat_completion_structured()` returns `None` when unconfigured — callers must take an explicit degraded path (rules / sentinel values), not invent content.
- Missing tender fields use the sentinel `NOT_MENTIONED = "未提及"` (`schemas.py`). Deviation responses stay `"待生成"` unless `get_mode() == "llm"`. Rule-based paths report `extraction_mode`/`mode: "rules"`.

### Long-running work
- Background jobs (KB ingestion, tender analysis upload, compliance check, batch deviation responses, batch section writing) use `task_manager.submit(type, fn, description, project_id=None)`; `fn(ctx)` reports via `ctx.report(progress, msg)` and can check `ctx.cancelled()`. `project_id` defaults to the request's `current_project_id`, and `fn` runs in a copy of the submitting context. Records live in memory while running (polls never hit the DB) and are written to the `tasks` table on submit/start/finish plus throttled progress (`PERSIST_INTERVAL`); results are stored as JSON. On startup `main.py` calls `task_manager.recover_interrupted()` (DB rows still pending/running → `interrupted` with `INTERRUPTED_MESSAGE`, keeps the newest `KEEP_FINISHED`) and `mark_interrupted_ingests()` (KB docs stuck in `ingesting` → `error`). `GET /tasks?project_id=&type=&active=&with_result=` lists history. Frontend: `pollTask` treats `interrupted` as terminal and retries through connection errors/5xx (a restarting server) with `reconnecting: true`; `TaskProgress` emits `failed` for failed *and* interrupted; views reattach on mount (`listTasks({active})` / `latestTask`) — Workspace batch, Deviation generate, Quality compliance (also restores the last report), Wizard tender analysis (also restores a finished-but-unapplied result), Knowledge ingest; the header task center (`components/layout/TaskCenter.vue` + `stores/tasks.js`, one shared poll timer) shows recent tasks.
- Section writing streams over SSE (`api/sections.py`): first event carries retrieval refs/mode, then `{token}` events, then `{done: true}`; content and `last_refs` are persisted only on success. A mid-stream failure yields `{done: false, error}` and saves nothing (the editor restores the previous text); `llm_client` raises instead of appending mock text once real tokens were produced. Retrieval/rerank is sync and runs via `asyncio.to_thread`.

### RAG pipeline (`services/rag/`)
Ingest (`ingestor.py`): docx parse (`parser/word_parser.py`) → `chunker` (heading-aware, tables as own chunks, small-chunk merging only within the same subsection to preserve breadcrumbs) → `enricher` (doc name + breadcrumb prefix, optional LLM summary) → `indexer` (BM25 via jieba + optional dense vectors) → optional `curator` (LLM knowledge items).

Retrieve (`retriever.py`): multi-query → BM25 ∥ dense recall → RRF fusion (rank-based, `RAG_RRF_K`) → LLM listwise rerank (0–10) → threshold `RAG_RERANK_THRESHOLD` (below it, return "no confident reference" rather than inject weak matches) → parent context expansion. Per-section `pinned_refs`/`excluded_refs` on `OutlineNode` force-include/exclude chunks. `knowledge_index` keeps BM25/dense indexes in memory, rebuilt from SQLite. Tuning knobs are in `core/config.py`.

### Bid workflow (project `stage`: created → tender_analyzed → outline_confirmed → writing)
1. `parser/document_parser.py` (`parse_document` dispatches by suffix; `.doc` is rejected with a hint) → `parser/word_parser.py` or `parser/pdf_parser.py` → `parser/tender_analyzer.py` (`analyze_document`). Both parsers feed `DocumentTreeBuilder` (in `word_parser.py`), so their output is identical in shape. The PDF parser (PyMuPDF) rebuilds paragraphs from positioned lines (per-page line gap and right edge — WPS character-grid lines end ragged, so a long line that ends mid-sentence counts as full), strips repeated headers/footers, running chapter headers and page numbers, skips the TOC page (also TOCs without page numbers), uses PDF bookmarks as heading styles when present and they cover the document's 第X章 structure (else only bold/enlarged short lines; Word's SimSun fake bold is fill+stroke, detected via `char_flags` with `TEXT_COLLECT_STYLES`), ignores invisible white fills when detecting tables and drops empty edge columns with no ruling, and stitches page-split tables (a row cut by the page break is merged back only when every continued cell was full to its bottom edge and some column had finished — otherwise it's a new row whose empty cells inherit the merged cell's id). Scanned/encrypted/garbled PDFs raise `PdfParseError` with a user-facing message; no OCR. The Word parser trusts Word heading styles/outline levels when a document has them (regex numbering heuristics only for unstyled docs; styled-but-sentence-like paragraphs are body), skips TOC, and returns `full_text` (document order, tables as ` | ` rows) plus flat `tables` with `cell_keys` (physical cell ids, so vertically merged cells are detectable). Always consume `full_text`, not top-level `sections`. 18 fields are LLM-first with regex supplement; `LLM_FIELDS` limits what the model may set. Clause markers (★/※/▲, and ☆/△/# only when the document defines them) mean whatever the document's own legend sentence says ("※标注的…不满足按无效投标处理" / "凡标有★条款…无效投标" / "★代表实质性指标…，#代表重要指标" → red line in `star_disqualification_items`; "…按评标因素扣分" / "重要条款…不作为认定无效投标的依据" → `important_items`); `marker_legend` records it. Rule-mode field values are cut at the next field label (PDF rows like "项目名称：X项目编号：Y").
   `parser/scoring_extractor.py` — deterministic 评分细则 extraction from scoring tables into `ScoringItem`s (package, category weight, points, criteria, sub-items, `response_type`: proposal/evidence/demo/compliance/price). Rows sharing a merged points cell are one item; rows sharing a merged factor-name cell with different points are one item with points summed. Header variants: a header cell spanning two body columns (category + factor name), no points column (points inside the factor name, "项目实施团队（16分）"), point steps "10.0（0,1,2）"; package labels "包2"/"第1包"/"A包"; header-only template tables don't count as a package. `target_package` selects the package being bid.
2. `generator/outline_generator.py` + `generator/rubric_planner.py` — level-1 chapters follow the rubric (proposal items each get a chapter; compliance/demo/evidence items are grouped), LLM output is passed through `ensure_coverage` so every scoring item has a chapter; expansion uses sub-items or the criteria's "内容包括：①…" points as section titles; word budgets follow points × `TYPE_WORD_FACTOR`. `OutlineNode.scoring_item_ids` is the traceability link.
3. `generator/section_generator.py` — prompt = global facts (hard constraints) + retrieved refs + sibling-section context + enterprise assets. Batch writing (`POST /project/{id}/sections/generate-batch`, background task) requires a configured LLM, writes only `ai_generate` leaf sections that aren't `reviewed` (empty ones unless `include_written`), re-reads the project per section, saves with `expect_content` so sections the user edited mid-run are skipped, and never saves mock-fallback output. Every AI/polish/batch/restore overwrite goes through `_save_section_content(..., version_source=…)`, which calls `services/version_store.py` after the commit: the previous text is snapshotted if it differs from the latest version (so manual drafts survive), max 30 versions per section; plain autosaves don't create versions.
4. `parser/deviation_engine.py` — `extract_from_structure()` walks the stored tender section tree: only the technical/service requirement part (title has 需求/要求, not 商务/须知/评标/合同/格式…), skipping 概况/一览表 sections, structural labels and 合计 rows; one item per requirement paragraph or requirement-table row, with `section` path and `level` (redline/important/normal) from the marker legend — a paragraph inherits its own heading's marker, and a short marked label paragraph passes its level to the paragraphs after it. `extract_requirements()` (flat keyword scan) is only the fallback for pasted text/old projects. LLM responses go 8 per call (`BATCH_SIZE`) with per-item retry; model drafts get `response_source="ai"` (UI shows 待核实 until edited). Batch generation only fills items still "待生成"; filled responses are bid commitments and are never overwritten.
5. `checker/compliance_checker.py` (multi-round LLM evidence check, keyword scan fallback) and `checker/quality_inspector.py` (8-dimension rule checks, polish). Dimension 7 is a real per-item coverage check (`checker/scoring_coverage.py`: 未承接/未撰写/要点缺失/篇幅不足/已覆盖, weighted by points). Dimensions that can't be assessed return `score=None`/"未检测" and are excluded from the overall score — an empty bid is rated "未撰写", never a passing grade.
6. `exporter/docx_generator.py` — python-docx, A4, real Heading styles, Word TOC/page-number fields, eastAsia fonts. Section Markdown is parsed with markdown-it-py (same rules as the frontend's markdown-it, `breaks: true`, so a single newline is a new paragraph): `#` headings in content are re-leveled to `node.level + 1…` (never at or above the outline node), whole-bold short lines stay non-TOC bold subtitles, lists get native Word numbering (one `abstractNum`/`num` per list block), tables are native with content-based column widths and repeating header rows. Mermaid images come from the frontend: export dialog renders every diagram with real Mermaid to PNG (`frontend/src/utils/mermaid.js`, `htmlLabels: false` so canvas export works) and `POST /project/{id}/export` sends `{code, image}` pairs matched by line-normalized code; without an image `diagram_renderer.py` (matplotlib, flowcharts only) is the fallback, then a code slot — it must never draw a placeholder diagram. `GET /project/{id}/deviation/export` writes the deviation matrix as a standalone native table.

### Frontend (`frontend/src/`)
Vue 3 + Pinia (`stores/project.js`, `stores/ai.js`) + vue-router (history mode; project views under `/project/:id/...`) + Element Plus + Tailwind. All HTTP goes through `api/client.js` (`request`, `uploadFile`, `streamSSE`, `pollTask`, `downloadPost`). Mermaid is configured once in `utils/mermaid.js` and loaded lazily where possible (it's large). No CDN dependencies — keep assets local.

Visual system ("纸墨"): colors are semantic tokens — RGB-channel CSS variables in `assets/main.css`, exposed to Tailwind as `paper/surface/raised/sunken/line/ink(-2/-3)/accent/seal/ok/warn/bad` and mapped onto Element Plus `--el-*` vars (light-N/dark-2 variants via `color-mix`). `html.dark` swaps the token values (`utils/theme.js`: system/light/dark, saved per browser, applied before mount). Use the tokens and shared classes (`card`, `chip chip-*`, `seg`/`seg-item`, `note note-*`, `meter`, `table-clean`, `icon-btn`, `field-label`, `hint`) instead of raw Tailwind palette colors (`slate-*`, `blue-*`…) so both themes keep working; SVG strokes need `class`/`style`, not presentation attributes, to resolve `var()`. Layout: every view wraps `components/layout/AppShell.vue` (collapsible left sidebar / mobile drawer, `TaskCenter`, `ModeBanner`, scrolling `<main>`; pass `fill` for full-height views like the workspace) and starts with `common/PageHeader.vue`. Stage/section-status labels live in `utils/project.js`. Bid previews render on `.doc-page.bid-doc-preview` (SimSun/SimHei like the Word export; the page stays light in dark mode). The brand mark is `common/BrandMark.vue` (inline SVG with fixed colors — navy tile, "E", vermilion seal square; not theme tokens); the favicon data URI in `frontend/index.html` is the same drawing, so change both together. `SettingsView` is one column with sticky top tabs (no second sidebar), sections addressed by `?tab=` (`model`/`retrieval`/`usage`/`appearance`, parts in `components/settings/`); unsaved LLM/embedding edits show a sticky save bar and a route-leave confirm. `/about` (`AboutView`) reads the backend version from `GET /health` (`api.health()` — site root, not under `/api/v1`; the Vite dev proxy forwards `/health`, `/docs`, `/openapi.json`) and live repo stats/recent commits for `shyrel666/EasyWrite` from the public GitHub API (`utils/github.js`, cached 10 min in sessionStorage; offline → links only). It has just two cards (hero + GitHub) — keep it that short.
